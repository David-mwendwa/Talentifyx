# Deploying Talentifyx

Two pieces: the React frontend on **Netlify**, the Express API on **Render**. They are
separate origins, which is what most of the configuration below is about.

## 1. Database — yes, you need MongoDB Atlas

Render does not host MongoDB, and the workspace Docker Mongo only exists on your machine, so
production needs a hosted database. The free **M0** tier is enough for this app.

If you already have the Atlas cluster used by another project in this workspace, you do not
need a second one — just use a different database name in the connection string:

```
mongodb+srv://<user>:<password>@<cluster>.mongodb.net/talentifyx?retryWrites=true&w=majority
```

The `talentifyx` path segment is the database; Atlas creates it on first write.

Two settings that will otherwise cost you an afternoon:

- **Network Access → allow `0.0.0.0/0`.** Render's free tier has no static outbound IPs, so
  an IP allowlist cannot work. The database is still protected by its credentials.
- **Database Access → a user with read/write on that database**, and if the password has
  URL-special characters (`@ : / ?`), percent-encode it in the connection string.

You do **not** need to seed jobs by hand: the API syncs from Arbeitnow on boot and finds an
empty database on the first deploy. Run `npm run seed:demo` against the production URI only
if you want the demo account to exist.

## 2. API on Render

Blueprint: `render.yaml` (root directory `backend`, `npm ci`, `npm start`, health check at
`/api/v1/health`).

Set these in the dashboard on first deploy — they are marked `sync: false` because they are
secrets or environment-specific:

| Variable | Value |
|---|---|
| `MONGO_URI` | the Atlas string above |
| `CLIENT_URL` | your Netlify URL, no trailing slash |
| `JWT_SECRET` | generated by Render automatically |

`PORT` is injected by Render; `server.js` reads it. `NODE_ENV=production`,
`SYNC_INTERVAL_HOURS` and `AUTO_SYNC` come from the blueprint.

`CLIENT_URL` accepts a **comma-separated list**, so Netlify deploy previews can be allowed
alongside the live site:

```
CLIENT_URL=https://talentifyx.netlify.app,https://deploy-preview-1--talentifyx.netlify.app
```

**Free-tier behaviour worth expecting:** the service is spun down after inactivity, so the
first request after a quiet period takes ~30 seconds to wake. That is also why the job sync
checks on boot rather than relying only on its hourly timer.

## 3. Frontend on Netlify

Config: `netlify.toml` (base `frontend`, `npm ci && npm run build`, publish `dist`, SPA
redirect, security headers, immutable caching for fingerprinted assets).

One environment variable, set in **Site configuration → Environment variables** *before*
the first build, since Vite inlines it at build time:

```
VITE_API_URL=https://<your-render-service>.onrender.com/api/v1
```

Note the `/api/v1` suffix. Without this the app falls back to a same-origin `/api/v1`, which
does not exist on Netlify, and every request 404s.

## 4. The cross-origin bits

Because the two halves are on different domains, auth cookies are cross-site:

- The API sets `SameSite=None; Secure; HttpOnly` in production — which means **the API must
  be served over HTTPS**, as it is on Render.
- CORS runs with `credentials: true` and an explicit origin allowlist. A rejected origin gets
  a 403.
- The frontend sends `withCredentials: true` on every request.
- `app.set('trust proxy', 1)` in production: Render terminates TLS at its proxy, and without
  it the rate limiter would bucket every visitor into a single client.

## 5. Deploy order

1. Create the Atlas cluster, user, and `0.0.0.0/0` network rule.
2. Deploy the API on Render with `MONGO_URI` and a placeholder `CLIENT_URL`. Confirm
   `https://<service>.onrender.com/api/v1/health` returns `{"status":"ok"}`.
3. Deploy the frontend on Netlify with `VITE_API_URL` pointing at that service.
4. Set the real `CLIENT_URL` on Render to the Netlify URL and redeploy the API.
5. Register an account on the live site and confirm you stay signed in after a refresh —
   that exercises the cookie, CORS and proxy configuration in one go.

## Troubleshooting

| Symptom | Cause |
|---|---|
| "Something went wrong" / a property error on first load | `VITE_API_URL` was missing **at build time**. The app fell back to a same-origin `/api/v1`, and the SPA catch-all answered it with `index.html` on a 200, so HTML got parsed as data. Set the variable and **rebuild** (Clear cache and deploy site) — a plain redeploy reuses the old bundle |
| Requests 404 on the live site | Same cause; `netlify.toml` now returns 404 for `/api/*` rather than the SPA shell, so the failure is visible |
| Login succeeds but you are signed out on refresh | `CLIENT_URL` does not exactly match the site origin, so the cookie is dropped |
| CORS error in the console | Same as above; check for a trailing slash or `http` vs `https` |
| API cannot connect to the database | Atlas network access, or an unencoded password |
| First request of the day hangs ~30s | Render free tier waking up |
